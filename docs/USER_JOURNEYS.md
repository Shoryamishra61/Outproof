# User journeys

HOME → consent/manual origin and explicit budget/time/group limits → COMPILE → exactly one accepted plan and proof → GO → next instruction → back to proof. Result headings receive focus; native labels and keyboard controls remain available. No recommendation feed, automatic reroll, autoplay or engagement loop exists.

Discovery, admission/hours and both directed routes must be supported before ranking. Missing facts produce typed failures. A failed compile returns to editable controls. Cancellation aborts the client request and discards stale responses. Rapid submit is bounded. GPS denial/timeout/inaccuracy leads to a manual option rather than fabricated precision.

GO rechecks evidence age, the current visit interval and the effective return deadline. An old plan requires recompilation. Voice is opt-in; text works if audio fails. Reload clears transient GO state; offline operation is not advertised as a newly verified outing. Fixture practice is explicitly labeled and unavailable in production.

The automated campaign separates 4,096 generated deterministic journeys, 300 adversarial cases, property/mutation checks, controlled browser flows, modest real production probes and real field trials. The first groups cannot substitute for physical outings. See `REQUIREMENTS_TRACEABILITY.md` and final reports for actual populations and limitations.

Visual thesis: a field notebook closes a decision. Three signature decisions are paper/grass semantic tokens, a ruled proof ledger beside one plan, and a single large GO instruction with a pedestrian-map handoff. Responsive tests cover 320–3840px, consent/error/retry/cancel states, keyboard focus, 200% CSS zoom and opt-in voice. Native screen-reader semantics are inspected; no human assistive-technology session or field Screen Ratio is claimed.
