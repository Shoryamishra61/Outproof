# Fixture product flow

Audience: a person with a short outing window who needs one defensible decision.
Job: enter limits, inspect one plan and proof, then practice the minimal GO flow.
Technical limit: only an explicit development fixture backend can return success;
the live compiler gate stays closed. Fixture destinations are fictional.

Visual thesis: **a field note with a receipt**. Preserve the existing warm paper,
grass ink, serif headings, semantic spacing and square-edged controls.

Three signature decisions:
1. Persistent FIXTURE identification on intake, result, proof and GO.
2. Duration and exact scoped cost precede a single chronological sequence.
3. Proof is a plain check ledger with source IDs; GO reduces to one next action.

No new design system, imported visual components, imagery or animation. Native
inputs, select, checkbox, details and semantic buttons handle keyboard and states.
Source observations retain their timestamps; their expiry is visible in proof.

Home -> compiling -> one fixture plan -> expandable proof -> GO practice.
Failures return to editable controls without relaxing rules. Compile results are
validated against the unchanged JSON schema using Ajv and matching generated
TypeScript contracts. Relational safety remains in the backend policy.

Both backend development flags plus development environment are needed. Frontend
requires Vite DEV and VITE_GROUND_RULE_FIXTURE_MODE=true. Production builds cannot
activate this demo through that flag. Default/live health remains unavailable.
