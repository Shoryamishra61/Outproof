# Bind walking facts to the actual route shape

The public Bengaluru city-origin receipt echoed the requested point, but an
independent fresh reproduction showed its path began 20.888 metres away. Neither
the connector's access nor its time was established. The original Chandigarh
city-origin route also fails the new endpoint check. Earlier accepted receipts
remain historical evidence; they do not certify these whole trips.

Decode the provider's bounded polyline6 and require both actual path endpoints
to meet the requested points within one metre of coordinate serialization
rounding. Missing, malformed or oversized geometry fails closed. A displaced
path returns an unsupported-constraint explanation asking the user to choose a
public footpath. Never invent a walking speed or connector, silently move the
origin, or expand the tolerance to recover a favourable acceptance.

Record the shape hash and both endpoint offsets in existing route metadata.
The successful-plan contract and all hard money/time/return rules remain
unchanged. This verifies mapped provider geometry, not physical access or safety.
Fresh Shanti Kunj and mapped Cubbon footpath round trips passed; city-centre
coordinates can legitimately fail.

An unsupported-origin failure may now carry an optional `suggested_origin`:
the actual path start/end, within 100 metres of the requested origin, only when
the venue endpoint is bound and no unmodeled ferry/toll exists. It is a proposal,
never a reachable route or accepted plan. The browser validates the failure,
limits the separation again, explains that travel to this point is unverified,
and requires an explicit selection followed by a new compilation. It preserves
every budget, time, walking, party and hard-rule control. The one-metre acceptance
threshold is unchanged. Missing sources or model failures cannot offer this repair.

Actual working-tree Bengaluru execution refused the original city point, passed
real source/routing/Gemma recompilation from its proposed route start, and refused
zero walking. `OUTPROOF_CONFIRMED_ORIGIN_LOCAL.json` records these separate inputs.
This is software evidence, not user consent obtained from a physical visitor,
connector evidence or physically confirmed accessibility. Public verification is
a separate release gate.

Ordinary failure serialization omits the absent proposal, preserving existing browser-session payloads. Pydantic minimum2.12 declares the conditional field-serialization feature; the already locked2.13.5 installation is unchanged. A newly proposed point is optional metadata: an older browser can refuse an unfamiliar payload safely while the frontend rolls forward. Rollback both app services to the same known green revision; never weaken schemas to accept an unrecognized proposal.
